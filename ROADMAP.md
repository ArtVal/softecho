# Роадмап

Краткий план и **условия перехода**, чтобы не тащить архитектуру раньше времени.

## Сделано

- Текстовые упражнения + локальный прогресс
- ASR (Vosk): «Сказать», диктофон, txt, буфер 120 с + «подождите»
- Разделение `engine` / `ui`, протокол `Command` + `tick`
- Portable-сборки: Windows / Linux / macOS (скрипты + GitHub Actions)
- **Настройки:** скачивание модели Vosk из приложения, hot-reload ASR без перезапуска
- Бренд **SoftEcho**, CI-артефакты `text` и `asr`
- Лестница занятия: **звуки → слоги → слова → фразы → скороговорки** (внутри ступени можно перемешать)
- **Экспресс-диагностика** → автоуровень; можно пропустить и выбрать уровень вручную
- Несколько встроенных наборов упражнений + выбор на главной (12 тем: starter, звуки, слоги, па-та-ка, рифмовки, скороговорки, быт, приветствия, семья, тело, еда, транспорт)
- **Карта произнесения** по слогам/словам/фразам + экран на главной
- **Автоподбор занятия** из карты (слабые первыми) + **повтор неудач** в сессии (приоритет растёт, «Не повторять»)
- GitHub Releases при теге `v*` (CI прикрепляет portable-архивы)
- Кнопка «Скачать модель» на главной, если Vosk не установлен
- **Windows portable:** release без чёрной консоли, иконка + метаданные exe, подсказка про SmartScreen в `ЧТОБЫ_ЗАПУСТИТЬ.txt`

Граница по умолчанию: **команды внутрь, события с краёв (ASR) наружу**. Не общая шина на всё приложение.

## Методология уроков (анализ, 2025)

**Источники:** [logoportal — ЗСС при эfferентной моторной афазии](https://logoportal.ru/statya-12857.html), [logopedrunet — этапы реабилитации](http://logopedrunet.ru/metodichka-dlya-logopedov-2-metodicheskie-osnovy-diagnostiki/), [rechistart — скороговорки после инсульта](https://rechistart.ru/blog/post/2024/nov/skorogovorki-posle-insulta/), [ASHA — dysarthria meta-analysis](https://apps.asha.org/EvidenceMaps/Articles/ArticleSummary/9382a196-a121-4633-82ca-7b74543f0d97), [Cuespeak](https://cuespeak.com/), [Tactus Apraxia Therapy (VAST + playback)](https://tactustherapy.com/app/apraxia/).

|-----------------|----------------------|

| Самопроверка + ASR | Допустимо, когда модель нет или человек устал [2] |

### Куда добавить скороговорки

**Не раньше фраз.** В методичках скороговорки — **этап автоматизации**, когда слог и короткое слово уже стабильны [3][4]:

1. Звуки (гласные, затем ранние согласные)
2. Слоги (открытые, повтор)
3. Слова (быт, тематика)
4. Фразы (2–4 слова, жёсткий контекст)
5. **Простые рифмовки** — короткие ритмичные цепочки вроде «гуси-гага, на траве дрова»: рифма и повтор ведут рот, мало смысла на раздумья. Ближе к считалкам, чем к классическим скороговоркам; можно раньше трудных twister (набор `read_aloud`, без нового движка)
6. **Скороговорки / ODK** — когда слог и короткое слово уже стабильны: «Милая Маша…», «Кар у Клары…», «па-та-ка» / «ма-ма-ма» на скорость

**Продуктовая ступень (кандидат):** простые рифмовки — JSON-набор на существующем `read_aloud`; классика — `ExerciseStage::Twister` или флаг `twister: true`. Не смешивать со слогами в одной сессии до уровня «Фразы»; трудные скороговорки — после N успехов на фразах.

**Правила занятия (из [3]):**

- медленно по слогам → отдельно трудные места → целиком медленно → ускорение;
- опора на ритм (в приложении: визуальный метроном / «прохлопывание» — позже);
- 10–15 мин × 2 в день, пауза каждые 5 мин — не гонять длинную сессию;
- если скороговорка «ломается» — откат на слог/слово с тем же звуком (связь с картой).

### Воспроизведение сказанного (playback)

**Зачем:** Cuespeak / Apraxia Therapy дают **запись → прослушать → самооценка** — это повышает осознанность, когда ASR ошибается или человек не уверен [5][6]. Текста partial недостаточно: нужен **свой голос**.

**Cascade для SoftEcho:**

1. **MVP:** во время «Сказать» писать PCM в кольцевой буфер (тот же pipe, что и Vosk); после паузы — кнопка **«Послушать»** + «Получилось / Не получилось» (ASR остаётся подсказкой, не единственным судьёй).
2. **Дальше:** сравнение с эталоном TTS (офлайн, опционально) — только если есть локальный голос.
3. **NO-GO:** облачная «оценка дикции»; автоматический вердикт без участия человека.

**Связь с картой:** playback не меняет `speech_map` сам — только после явной самопроверки или подтверждения ASR.

### «Иногда активируют речь» — два смысла

| Смысл | Решение в продукте |
|-------|-------------------|
| **Педагогика:** рифмовки и ODK «включают» моторную речь после пассивного этапа [3][4] | Сначала простые рифмовки; классический twister — после N успехов на фразах / уровень «Фразы+» |
| **UX:** микрофон не должен висеть вечно | Уже: «Сказать» / «Готово»; для скороговорок — **явный старт** + короткий буфер записи |

### ODK / губы, язык, голос

Два слоя, не смешивать:

- **В приложении:** речевые повторы `/pa/ /ta/ /ka/`, `/pataka/` — те же губы и язык, но со звуком. Доказательная база при дизартрии [7]. Микро-набор «Артикуляция» перед рифмовками: 5 секунд на слог, счёт повторов — без жёсткого ASR, playback + самопроверка.
- **До занятия (в приложении — схемы, не ролик):** крупные схемы движений губ/языка/выдоха + **ссылки на чужие видео снаружи** (таблица ниже). Не отдельный тип упражнения, не копия чужого файла, не встроенный плеер.

Cascade: разминка или «па-та-ка» → простые рифмовки → трудные скороговорки, когда фразы уже идут.

**Общедоступные видео (смотреть можно, вшивать нельзя — чужое авторское право; CC-набора для взрослых после инсульта нет):**

| Что | Где |
|-----|-----|
| Комплексы «базовый» / «основной» (губы, язык, выдох со звуком) | Канал Александры Викторовой, логопед-афазиолог; сайт [logo-vav.ru](https://logo-vav.ru/) — искать «Викторова Александра артикуляционная гимнастика» |
| Короткие уроки при афазии Брока (растормаживание, не детская зарядка) | Маргарита Сергеева, Рутуб, [пример урока 4](https://rutube.ru/video/398b1ff9de17389903123ed99ed26522/) |
| Короткий ролик медлогопеда | ГКБ №52, [упражнения при афазии](https://rutube.ru/video/f3fa74003f7f663e4390c37ac8e51fd7/) |
| Длинный фонетический комплекс (~36 мин) | [Начальные упражнения](https://rutube.ru/video/d31cfa3d1a927a0649e32e3a32fafa3e/) |

В приложении для разминки: **схемы + ссылки**, не свои и не сгенерированные клипы. Детские ролики («улыбка — трубочка — лошадка») на YouTube — слабый ориентир. NHS: видео для лица после пареза, не речевая гимнастика. Нейросеть можно только на черновик схемы; язык во рту генератор систематически врёт — в продукт как эталон не класть.

## Диагностика → план → прогресс → редактор (продукт)

Цель: понимать, **что человек уже произносит**, и на этом строить занятия — без клиники и без облака.

**Лестница тренировки (занятие с выбранного уровня и выше):**

1. **Звуки** — гласные (А, О, У…) и ранние согласные (М, П, Б…): сказать / отметить самому.
2. **Слоги** — открытые слоги (ма, па, ба…): сказать / отметить самому; голос сверяет слог, не фразу.
3. **Слова** — выбор и произнесение коротких бытовых слов.
4. **Фразы** — сборка и чтение коротких фраз.
5. **Скороговорки** — после фраз (или при ≥70% «получается» на фразах набора): медленно → быстрее.

Внутри ступени порядок можно перемешать. Между ступенями — нет.

**Экспресс-диагностика (уже в приложении):**

- короткий прогон: до 2 заданий на ступень (звук → слог → слово → фраза);
- голос или самопроверка;
- уровень = первая ступень, где меньше половины верных (иначе «Фразы»);
- уровень пишется в `progress.json`; диагностику можно **пропустить** и выбрать уровень вручную.
- занятие без уровня открывает выбор уровня.

**Cascade (порядок продукта дальше):**

1. ~~**Карта произнесения**~~ — сделано: «получается / почти / нужна практика» в `progress.json`.
2. ~~**План упражнений**~~ — сделано: слабые из карты первыми + возврат ошибок в очередь занятия.
3. **Прогресс по навыку** — тренд, повторная диагностика, отчёт.
4. **Редактор упражнений** — правка/добавление наборов из приложения.

**Данные (локально):** `progress.json` — уровень, набор, счётчики, `speech_map` по нормализованным ключам (слог «ма ма ма» = «ма»); наборы — встроенные JSON; редактор позже — каталог данных пользователя.

| Шаг | GO | NO-GO |
|-----|----|-------|
| Диагностика | есть ASR или честная самопроверка; короткий прогон | «ИИ-диагноз афазии» / облачная оценка |
| План | есть уровень или карта; план = выбор из наборов | отдельный «умный» сервер подбора |
| Прогресс по словам | пишется локально рядом с `progress.json` | синхронизация с врачом без GO клиент–сервер |
| Редактор | правка локальных JSON; валидация как у starter pack | онлайн-CMS / аккаунты |

## Клиент–сервер (когда понадобится удалённый движок)

**GO, если** хотя бы одно:

- один движок обслуживает **несколько клиентов** (планшет + ПК, терапевт + пациент);
- нужна сессия **не на той же машине**, где UI;
- прогресс / наборы живут на сервере и синхронизируются.

**Как делать (без полной шины):**

1. Тот же `Command` по сети (клиент → сервер).
2. События изменений наружу: `EngineEvent` (`ScreenChanged`, `Utterance`, `PleaseWait`, `ReadyAgain`, …).
3. UI подписывается на поток событий + при необходимости редкий snapshot.

**NO-GO:** шина «ради событийности», пока один локальный UI и один `Engine`.

## Шина событий / event-bus (отдельное решение)

Не путать с «события ASR» и с сетевым `EngineEvent`.

**GO на общую шину (pub/sub), если** выполнено **несколько** пунктов:

- ≥2 независимых подписчика на одно и то же событие (UI + лог + метрики + сеть + второе окно);
- появляются плагины / модули без прямого доступа к `Engine`;
- оркестрация размазана, явный владелец состояния мешает больше, чем помогает.

**NO-GO / отложить, если:**

- один UI и один `Engine` (текущий случай);
- достаточно `Command` + исходящих `EngineEvent`;
- цель — только «красивая архитектура» или будущий CS без реальных подписчиков.

**Cascade:** сначала `Command` + outbound-события → сеть → шина только при многих слушателях.
